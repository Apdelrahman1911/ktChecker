# Diagnostic breadth: independently authored source, not execution credit

Kotlin **2.4.21**, JVM target17, language/API2.4. This additive plan contains
**15 existing compiler IDs × six source kinds =90 fixed source files**.
It does not append to the98 ordinary pairs or change the six nullability IDs,
30 nullability files,18 type-boundary supplemental files,16 unsupported KMP
graphs,443 compiler mappings, or global1,663 × eight-context inventory.
All initial execution fields remain `not_run`; implemented/tested/qualified
stage transfer is zero. Historical attempts and their evidence are not reused.

## Three separate, closed routes

| Exact selector | Existing activation group | Authored source calls | Option-off calls | Version denial | Shared controls | Maximum reservations |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `diagnostic_breadth_default` | enabled_when_validated |30|0|1|4|35|
| `diagnostic_breadth_advisory` | advisory |30|5|1|4|40|
| `diagnostic_breadth_opt_in` | opt_in |30|5|1|4|40|

Each route selects exactly five IDs, in the literal reviewed order. The six
kinds are positive, negative, boundary, applicability, suppression, regression;
scheduling is kind-major. Regression files already contain exactly two leading
newlines plus their positive source bytes: there is no runtime source rewrite.
Option-off calls reuse the *unchanged positive path and digest*, not a new source
or a seventh authored kind. Denial requests2.4.20 and must produce a real
pre-runtime refusal, not an inferred absence of a child. The four existing control
bodies are unchanged and run once.35/40 reservations imply at most34/39 possible
child-capable calls, never proof of execution.

There is no breadth `all` selector, batching, retry, fallback, replacement,
budget pooling, continuation, resume, or cross-run merge. Smaller owner bounds,
owner stop, failed receipts, deadlines, cleanup or quarantine can leave the
schedule incomplete. Existing global48-call,1,200s aggregate,90s per-job,
256MiB evidence,16MiB job reserve and8MiB terminal reserve bounds remain intact.
Every call still goes through the unchanged sealed provider executor and needs
its own existing nonserializable permit. Neither JSON nor a selector is authority.

## Independent source oracles

`diagnostic-breadth-source-evidence.json` binds tagged primary compiler factories,
checker predicates, CLI flag definitions and upstream marked tests to the pinned
48,793,351-byte Kotlin tag archive. Only regular source entries were read as
data. No upstream harness, candidate compiler, provider, native helper or model
was used to create an oracle. Upstream quotations retain Apache2.0 attribution;
this does not select a license for this repository.

For positives and regressions, the selected diagnostic requires its exact
upstream/stable-ID pair, declared severity, multiplicity, authored path/digest,
and independently declared token region in both actual raw and mapped channels.
Their actual point/message multisets must agree. CLI locations are one-based
lines and zero-based UTF-16 **points**, not fabricated end spans. Authored regions
are bounds on a later actual point, not observations. Sources contain no diagnostic
markers to be interpreted as emitted output.

The invalid Int-returning `operator hasNext` necessarily also emits
`INAPPLICABLE_OPERATOR_MODIFIER`. This ID has no entry in the current443 mapping.
Its exact named raw ERROR at the separately declared `operator` region is required
and retained. It is not suppressed, dropped, mapped inventively, or credited as a
sixteenth rule. The selected ERROR is mapped; the actual compiler **and provider
remain failed**, even when the expected error oracle matches.

Ordinary warning positives require supervised exit0 and the selected warning in
both channels. Selected-absence alternatives require exit0, no selected emission
in either channel and no unexpected raw/mapped errors. Every other non-error
diagnostic is retained and allowed; neither exit0 nor a matched oracle means
clean compilation, complete diagnostic coverage or project coverage. Parser
malformed/unparsed status is retained separately; a locationless informational or
experimental-option warning is not erased to manufacture a clean run.

Boundary expectations are per source, not inferred from the word "boundary":
smartcast-nonnull `orEmpty` still expects a warning. Const-alias duplicate `when`
labels (KT-11971) and const-valued blank `trimMargin` prefixes are deliberate
**retained blind spots**, not safe alternatives. Other boundaries preserve
extension protocol resolution, delegation covariance, distinct DSL markers,
unbounded generics, explicit identity equality, delegated write effects,
integer-literal ambiguity, internal API visibility and `IgnorableReturnValue`.

Warning suppression files contain both a function-locally suppressed case and a
separate unsuppressed control. Exactly the control's independently declared region
may emit the selected warning. The five default ERROR suppressions and explicit
API ERROR suppression stay **unknown and unvalidated**, even after exit0; all
actual errors and `ERROR_SUPPRESSION` warnings remain visible. Consequently the
default and opt-in schedules cannot validate all their expectations.

## Options and activation caveats

All inputs retain the exact base `-jvm-target 17 -language-version 2.4 -api-version 2.4`.
Array equality, overwritten assignment, CanBeVal, conversion and nonnull-call
inputs add `-Wextra`. Warning option-off calls keep those on flags and add the
exact `-Xwarning-level=<SELECTED_ID>:disabled`. This is actual reporting control,
not an assumption that removing `-Wextra` disables every factory in an "Extra"
section. Tagged CommonExpressionCheckers registers array equality and conversion;
the existing production activation-map discrepancy remains outside this test-only
change and is recorded as a gap, not silently fixed.

Explicit API uses `-Xexplicit-api=strict` versus `-Xexplicit-api=disable`.
Return-value checking uses `-Xreturn-value-checker=full` versus `disable` on an
**unannotated** positive. Feature annotations are not assumed legal under disable;
the `IgnorableReturnValue` boundary is scheduled only with full enabled.

## Evidence and completion

The existing START capture preserves all90 files plus six pinned metadata/test
files, including unselected scopes. Exact compiled declarations, not manifest
row order or arbitrary JSON, determine the calls. Paths are registered once even
when option-off reuses a positive. Every returned actual job is retained before
receipt checks; after an executor failure only an unvalidated observation can be
recorded, and the original failure is rethrown without another call.

Private checkpoints retain actual failed tasks, full named-plus-residual raw
diagnostics, mapped findings, parser status, per-kind counts, the fixed schedule,
denial/control receipts and independent START drift checks. Receipt completeness
is informational. A future advisory local-schedule completion requires every
actual receipt, oracle, denial, shared control and current START check. It is never
ordinary six-kind completion, global matrix promotion, independent qualification
or release acceptance. Default/opt-in unknown suppressions keep those runs
incomplete. No breadth route writes the ordinary external latest sidecar.

Java interop suites, KMP/refines graphs, Kotlin/Native/iOS, alternate JDK/OS tuples,
libraries, large projects, real-world false-positive rates and performance remain
gaps. Source-authored IDs become119 (98+6+15), leaving324 mappings outside those
authored sets; the16 unsupported planned graphs stay visible, not subtracted from
the scope. All443 mappings remain unqualified by this source addition.
